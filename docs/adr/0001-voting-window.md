# ADR 0001. 투표 시간 정책

- 상태: 확정
- 날짜: 2026-08-10

## 배경

기존 문서 세 곳의 내용이 서로 달랐다.

| 출처 | 내용 |
| --- | --- |
| 기획서 | 코스 확인 후 1시간 투표 |
| API 명세 v1 | 10분 투표 |
| 구두 지시 | 방 생성 후 1시간, 재투표가 되면 그때가 10분 |

셋 다 그대로 구현할 수 없어 두 가지를 확인했다.

**질문 1. 1시간 창의 시작 기준점은?**
→ 답변: **코스 생성 완료 시점**

**질문 2. 재투표 10분이 시작되면 전체 확정 시각은?**
→ 답변: **해당 항목만 10분, 코스는 1시간 유지**

## 결정

1. `Course.votingEndsAt` = 코스 생성 완료 시각 + **60분**.
   생성 이후 **어떤 경우에도 변경하지 않는다.**
2. 항목이 과반수 싫어요로 재생성되면, 교체된 새 항목에 한해
   `CourseItem.revoteEndsAt` = `min(재생성 완료 시각 + 10분, course.votingEndsAt)`.
3. 코스 전체 자동 확정 판정은 **오직 `votingEndsAt` 하나만** 본다.
   재투표는 확정 시각을 앞당기지도 늦추지도 않는다.

즉 재투표 창은 "항목 단위로 더 짧게 닫히는 창"이지 코스 타이머가 아니다.

## 왜 이렇게 했나

**"방 생성 후"가 아니라 "코스 생성 완료 후"로 잡은 이유**

약속방을 만든 뒤 참여자들이 취향을 제출하기까지는 기본 5시간이 걸린다.
방 생성 시점부터 1시간을 세면 투표할 코스가 존재하기도 전에 창이 닫힌다.
투표는 코스가 있어야 시작할 수 있으므로, 시작점은 코스 생성 완료 시점이다.

**재투표가 코스 타이머를 건드리지 않게 한 이유**

재생성 때마다 확정 시각이 밀리면 종료 시각이 예측 불가능해진다.
한 명이 계속 싫어요를 눌러 확정을 무한정 미루는 것도 가능해진다.
반대로 재생성이 확정을 앞당기면, 다른 항목에 아직 투표하지 않은 사람의 기회를 뺏는다.

확정 시각을 처음부터 고정해두면 참여자에게 "언제 끝나는지"를 한 번만 알려주면 되고,
그 약속이 깨지지 않는다.

**재투표 창을 코스 종료시간으로 캡한 이유**

투표 종료 5분 전에 항목이 교체되면 10분 창은 확정 이후까지 이어진다.
확정된 코스에 투표를 받는 것은 의미가 없으므로 `min()`으로 자른다.

## 결과

- 참여자는 큰 시계 하나(코스 60분)와, 교체된 항목에만 붙는 작은 시계 하나를 본다.
- 투표 화면 우측 패널이 코스 시계, 항목 카드 안쪽이 재투표 시계다.
  UI 구조 자체가 정책을 설명한다.
- 항목당 재생성은 3회로 제한한다. 도달하면 `LOCKED`으로 두고, 광고 확인 후 횟수와 해당 항목 투표를 초기화할 수 있다.
